# Free GEO Check

The check sends three independent local discovery questions to OpenAI's Responses API with required web search. The business name and domain are withheld from discovery prompts to avoid forcing a mention. A fourth structured-output request extracts other named providers with verbatim evidence and produces recommendations. No website crawler runs and no invented fallback data is displayed.

## Run locally

Requires Node 22.16+ and the installed dependencies (`npm ci`). Create an ignored `.env.local` in the project root using `.env.example`, and set:

```dotenv
OPENAI_API_KEY=your-server-side-key
GEO_MODEL=gpt-5.6-terra
```

Start `npm run dev -- --host 127.0.0.1`, then open <http://127.0.0.1:3000/geo-check>. The local API reads current server environment files for every new request, so replacing `.env.local` takes effect on the next check. Existing jobs retain the credentials they started with. Missing keys produce an explicit service-unavailable response. Never put the key in a `VITE_` variable: those variables are public browser configuration.

Vite runs the API at `/api/geo`. Reports and daily counters are stored in the ignored `.local-data/geo/reports.json`, written atomically with restricted file permissions and denied by Vite's file server. Run a single dev-server process per checkout. Local data is independent of production DynamoDB. Interrupted local jobs become failed/partial after eight minutes rather than polling indefinitely.

## Deploy with the existing Amplify backend

1. Configure an Amplify **secret** named `OPENAI_API_KEY` for the target branch. For an AWS sandbox, run `npx ampx sandbox secret set OPENAI_API_KEY` and enter the secret interactively. Do not commit the key or add it to `amplify_outputs.json`.
2. Deploy the existing backend and frontend using the project's Amplify pipeline. The added resources are two Node 22 Lambda functions, a regional API Gateway REST API and a private DynamoDB table. No cloud deployment is performed by local `npm run dev` or `npm run build`.
3. Ensure the generated `amplify_outputs.json` is available **before** the frontend build. It must contain `custom.geoApiUrl`, generated by `backend.addOutput`. The checked-in historical outputs do not include the new endpoint. Alternatively set the public frontend variable `VITE_GEO_API_URL` to the deployed `/geo` API URL.
4. `GEO_MODEL` can override the model at backend synthesis time; default `gpt-5.6-terra`. Use a Responses model supporting both web search and structured outputs and verify that the project has access. Reasoning models use low effort and each request is capped at 4,000 output tokens and 55 seconds. Discovery calls allow at most one search tool call each.
5. Optional kill switch: set `GEO_ENABLED=false` at backend synthesis time and redeploy to reject new submissions while keeping existing reports readable.

Allowlisted origins are `https://mapsuche.de`, `https://www.mapsuche.de` and the two local port-3000 origins. Add an exact preview origin in both API handler and CDK CORS configuration if needed. The existing CSP already permits regional `execute-api.eu-central-1.amazonaws.com` endpoints.

Each job uses up to four paid OpenAI requests and three web searches. “Free” refers to the visitor; the configured OpenAI account pays the API charges. Daily admission limits are three checks per hashed source IP and 100 checks across the entire deployment (UTC day). DynamoDB transactions enforce both counters atomically before queueing a job. Counters include failed jobs. API Gateway throttles requests separately. These are request caps, not a currency budget: also configure account-level spend controls for the chosen provider/model.

## Persistence and access

- POST `/geo/checks` accepts `{ business, website, city, service, consent: true }` and returns HTTP 202 with `{ id, token, createdAt }`.
- GET `/geo/checks/{id}` requires the private `X-Geo-Token` header. Wrong/missing tokens and expired/missing records return the same 404 response.
- DELETE `/geo/checks/{id}` requires that token and a terminal job state. It deletes the live report; provider retention and existing backups are separate.
- Browser links use `?id=...#token=...`. The token is not sent in URLs to the server. Anyone with the complete link has access to the report. The browser stores up to 30 ticket references; the server stores only a SHA-256 token hash and exposes no public report listing.
- Jobs transition `queued → running → completed | partial | failed`. An atomic claim prevents duplicate asynchronous Lambda deliveries from spending API credits twice. Worker progress is saved after each question. The API flags an idle job after eight minutes. The worker is limited to five minutes and async retries are disabled.
- Authentication, permission, billing, model-access and invalid-request failures stop further discovery requests immediately. Reports show a safe, specific explanation; raw provider error bodies are never displayed because they may contain credentials. For a 401 authentication failure, replace the rejected key in `.env.local` (local) or the Amplify secret (production), then restart/redeploy. Previous reports retain their original outcome.
- Reports expire after 30 days. GET enforces expiry immediately; DynamoDB TTL deletes later. The table is retained across stack removal and has point-in-time recovery. Backups have separate retention. Local storage is pruned during subsequent requests.

Reports retain the original answer text, clickable citation annotations, questions, provider response IDs, returned model IDs, token usage, timestamps, prompt version, deterministic mention/citation metrics, extracted competitors with supporting quotations, and AI recommendations. Name detection normalizes case, accents and punctuation with word boundaries; it does not infer aliases. A citation is counted only for an actual API citation whose hostname is the target domain or a subdomain, never a lookalike or a plain textual URL. Percentages use successful answers as their denominator; all-failed reports have null metrics. Competitor quotes must occur verbatim in the cited answer and include the extracted name.

The results are a small, time-specific API sample. They do not measure all AI systems or the ChatGPT application. Recommendations are AI-generated and do not establish that a technical website audit was performed.

## Languages

All four GEO pages, the homepage GEO promotion and the services card use the URL's language (`/en/...` or `/de/...`). Interface messages, errors, counts, date formatting and consent text update when the language changes. The switcher links to the equivalent page and preserves the report ID and token fragment. Old unprefixed report URLs redirect to English without dropping those parameters. New check submissions include `language: "en" | "de"`; discovery questions, AI answers and recommendations use that language. Legacy API requests without a language default to German. Saved AI answers, questions, recommendations and evidence quotations remain in their original report language when the interface language changes, preserving citation offsets and the evidence used to calculate metrics. The results page identifies this language explicitly. Changing the interface language does not make additional AI calls.

## Verification

```bash
npm run test:geo
npm run check:geo
npm run build
```

`npm run check` checks the entire frontend. `check:geo` checks the new shared/server code and the Amplify backend. Tests use controlled OpenAI responses and temporary local databases; they do not spend API credits or deploy cloud resources. Before enabling production, configure the key, deploy, run one real report, refresh its private URL, verify it in the dashboard, and delete it. This live-provider/deployed-AWS smoke test requires credentials and deployment. See [indexing and hosting setup](INDEXING.md) for the prerendered frontend and route rewrites.
